# Level 13 → Level 14

**Objective**
Retrieve the password for `bandit14` stored in `/etc/bandit_pass/bandit14`. For this level, no password is given to start. Instead, you extract the provided private SSH key into a custom key file (`~/bandit14key`) to log in automatically without entering a password.

**Technical Details**

- **Target Username:** bandit14
- **Target Host:** `bandit.labs.overthewire.org`
- **SSH Port:** 2220
- **Custom Key File:** `~/bandit14key`
- **Target Password File:** `/etc/bandit_pass/bandit14`
- **Level 14 Password:** `aaWecNkG4FhxJQxz07uiwzVP6bJiYS65`

> **Note:** A private SSH key is a cryptographic identity file, not an executable script. OpenSSH requires strict owner-only read/write permissions (`chmod 600`), or it will refuse to authenticate.
> 

**How to Solve**

**Step 1: Create and Populate `~/bandit14key`**
Save the provided private SSH key into your custom file `~/bandit14key`:

Bash

```
cp sshkey.private ~/bandit14key
```

*(Or create `~/bandit14key` directly and paste the RSA private key string inside).*

**Step 2: Enforce Strict File Permissions**
OpenSSH requires private key files to be protected from other system users. Set strict read/write permissions for your user account:

Bash

```
chmod 600 ~/bandit14key
```

> CRITICAL: Leaving file permissions loose (such as `644` or adding `chmod +x`) causes OpenSSH to throw a `Permissions are too open` warning and cancel the connection.
> 

**Step 3: Connect Automatically via SSH (No Password Required)**
Pass your saved key file to `ssh` using the `-i` (identity) flag to log directly into the target server:

Bash

```
ssh -i ~/bandit14key -p 2220 bandit14@bandit.labs.overthewire.org
```

**Step 4: Retrieve the Bandit 14 Password**
Once authenticated and inside the `bandit14` shell, execute `cat` on the password path:

Bash

```
cat /etc/bandit_pass/bandit14
```

**Output:**

Plaintext

```
aaWecNkG4FhxJQxz07uiwzVP6bJiYS65
```

**Technical Breakdown: SSH Key Authentication & Identity Files**

**1. Zero-Password Key Authentication**

- **Identity Flag (`i`):** Instructs `ssh` to present `~/bandit14key` during the cryptographic handshake rather than prompting the user for an interactive password.
- **Public/Private Key Match:** The server verifies the cryptographic signature generated by your local private key against user `bandit14`'s authorized keys and opens the shell directly—bypassing password prompts entirely.

**2. Strict Permission Model (`chmod 600`)**

- **Access Control:** Permissions set to `600` (`rw-------`) ensure only your user can read or modify the private key file.
- **Client Enforcement:** The OpenSSH client strictly inspects key permissions prior to sending network traffic. If group or world read access is detected, the process aborts execution immediately to prevent identity theft.

**Key Takeaways**

- **Identity Flag (`i`):** Use `ssh -i <keyfile>` to authenticate seamlessly using private key credentials.
- **Key File Security:** Always restrict access permissions using `chmod 600 keyfile` so the SSH client accepts the key.
